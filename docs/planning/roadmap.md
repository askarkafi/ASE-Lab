# High-level roadmap

**Status:** Preliminary and intentionally unscheduled.

This is **not** a semester calendar or a commitment to specific deliverables. The detailed roadmap will be agreed only after the architectural direction and first implementation slice are validated.

## Current — project foundation

- Define a clear public project identity and documentation structure.
- Establish architectural goals, assumptions, and open questions.
- Agree on criteria for SDK evaluation and the first small implementation slice.

## Next — architecture validation and first executable slice

- Examine candidate SDK capabilities and extension boundaries.
- Select a bounded task and define objective acceptance criteria.
- Build, test, and document one real end-to-end component or capability.
- Publish reviewed findings and implementation updates when ready.

## Later — incremental product evolution

- Add specialized engineering capabilities, tools, skills, and controlled execution workflows as needed.
- Improve maintainability, runtime integration, observability, and safety.
- Consider additional agents, orchestration, and interoperability when justified by use cases.

## Possible future directions

Independent student extensions and controlled research studies may be undertaken after the relevant engineering foundation exists. See [future extensions](future-extensions.md).
